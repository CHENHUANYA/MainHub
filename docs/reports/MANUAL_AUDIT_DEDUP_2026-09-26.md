# 人工測試：重複歷程修正

2026-09-26，使用者在 CNC 測試部署的維修工單視窗發現同一建立事件重複顯示。
對應問題 `ISS-20260926-7d78b5`、工單 `c9883d44`。

## 修正

- 儲存歷程原本只查 `legacy:` 事件是否存在，導致已存在的 `create:` 事件在後續存檔再次寫入。改為核對該實體的全部事件識別碼。
- 前端依來源、完整時間、操作者、動作及內容移除顯示副本；不刪資料庫的歷史紀錄，也不合併不同操作。
- 狀態轉換已在標題顯示時，不在欄位明細再顯示一次。
- 維修視窗的問題 ID 留在標題；問題描述留在表單。若原始通報與工單描述不同，仍另顯示原始通報。
- 第二次畫面回報顯示同次操作的問題同步與工單狀態變更仍重複列出。v2 僅在同操作者、同步晚於工單不超過一秒、狀態相符、所有欄位變更均已包含且唯一對應時，將同步事件合併顯示；資料庫兩份原紀錄保留。多重對應、不同操作者、延遲或有額外變更時仍各自顯示。
- 實際 HTTP 回應設定前端資源快取一小時，截圖仍使用舊版維修頁面程式，導致問題描述重複。v2 更新維修頁面兩份腳本的資源版本，避免重新整理仍命中舊快取。
- 使用者截圖確認維修頁已顯示四項操作，之後由本人完成並儲存模擬工單。主管頁仍引用未更新版本的共用腳本；v3 將主管、操作員及管理頁的共用歷程腳本版本一併對齊，並移除主管歷程標題與明細重複的狀態變化。
