# 自行改密碼與臨時密碼流程

使用者指出先前尚未親自測試密碼功能，並要求首次登入、自行更改與管理員協助重設皆須測試。
本輪補齊功能及工程驗證。使用者已依指引完成首次設定、自行更改、管理員協助重設與臨時密碼轉個人密碼，並回覆「可以了，都成功了」。
人工結果及未另確認的跨裝置／取消項目分別記於 [測試指南](../guides/PASSWORD_ACCEPTANCE_ZH_TW.md)。

## 變更

- 四種角色及共用工作頁的頁首新增「更改密碼」；驗證目前密碼後，僅能更改登入者本人的密碼。
- 錯誤舊密碼採限流；新密碼不得與舊密碼相同或使用弱預設值。保留版本衝突保護，不覆寫其他同時發生的帳號變更。
- 成功後提高憑證版本、撤銷全部登入並清除目前 Cookie，返回登入頁提示使用新密碼。
- 管理員重設改為頁內臨時密碼表單，輸入需確認一致；本人下次登入必須另設個人密碼。
- 管理員不能透過重設端點繞過自己的舊密碼檢查；逐筆新增帳號也與批次匯入一致，首次登入須更換臨時密碼。
- 登入頁提供忘記密碼的處理說明。未建立郵件／簡訊驗證，也未新增無身分驗證的找回入口。
- 取消清空密碼欄位，處理中避免重複送出及關閉；密碼不放入 localStorage、回應或工程報告。
- 同步角色流程及舊瀏覽器驗證工具；角色 smoke 檢查不再因登入失敗自行替帳號重設密碼。
