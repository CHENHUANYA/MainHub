# 正式公司驗收準備

本指南銜接現有清單第 7～9 項：正式文件品質、兩位人員獨立導入、版本及簽收核對。
每家公司由文件提供人、內容審閱人及導入人員共同準備；尚未指定的人員與未收到的文件保留待辦。

## 1. 建立每家公司的紀錄

各自取得 [正式公司文件品質與交付核對表](../../templates/FORMAL_COMPANY_ACCEPTANCE_ZH_TW.md)
及 [導入驗收紀錄表](../../templates/COMPANY_ACCEPTANCE_RECORD_ZH_TW.md)，複製到各公司的證據目錄。
前者記錄文件與答案審閱，後者記錄依 SOP 實際操作的結果，互填紀錄位置。
填好的紀錄及正式文件由公司保管，不放回會被封裝的共用 `templates/` 目錄。

本版基礎包是 `mainthub-company-template-20260929-password.zip`，SHA256 以 ZIP 旁的同名 `.sha256` 檔及安裝驗證報告為準。
本指南與兩份空白核對表已納入本版 ZIP；完成後的公司紀錄另存，不覆寫包內模板。
先確認本版乾淨安裝驗證通過，再進入正式手冊與另一位使用者的獨立測試。

## 2. 收齊文件與適用關係

填寫新表第 1～3 節：公司設定、部署安排、人員、核准文件清冊與設備適用關係。
逐檔留下實際版本及 SHA256，例如在 PowerShell 執行：

```powershell
Get-FileHash -LiteralPath "C:\公司驗收\company.json" -Algorithm SHA256
Get-FileHash -LiteralPath "C:\公司驗收\核准手冊.pdf" -Algorithm SHA256
```

將結果填入紀錄，保存核准依據及原件；公司設定不包含帳密。
核准文件須符合現有解析型態；若 PDF 無可擷取文字，先記錄缺口與處理結果。
設備適用證據必須指到原文或核准關係文件，詳見 [設備對照與拒答邊界](RAG_DEMO_ACCEPTANCE_ZH_TW.md#設備對照與拒答邊界)。
尚缺正式文件或適用依據時，填上負責人及待補資料，維持待驗收。

## 3. 準備並審閱五題

每家公司至少兩題有答案、兩題資料不足、一題設備不符。先在表中寫好問題、預期答案或缺口與來源依據，
再依 [查詢品質流程](RAG_DEMO_ACCEPTANCE_ZH_TW.md) 從畫面查詢。
逐題保存完整回答、回答 ID、引用、頁碼、時間及版本；內容審閱人逐句比對事實、動作與設備對象。
不足題需核對有無猜測或借用別台設備步驟；不能只憑「資料不足」四字判為通過。
發現問題時保留原始失敗，修正後以原題重跑並另存紀錄。

現有 `verify_company_rag_quality.py prepare/run` 用於 MOCK 工程部署，不能用來匯入正式公司文件或代填真人審閱。

## 4. 兩位人員獨立導入並核對交付

先填導入表的雙人安排，再各自使用同一固定包及 [公司導入 SOP](COMPANY_DEPLOYMENT_SOP_ZH_TW.md)
完成登入、角色流程、批次導入、查詢及備份還原。每個卡住的步驟都要留下紀錄。
若採不同主機，仍另附同機雙部署的隔離證據，標明實際包、設定及驗證範圍。
既有 MOCK 工程報告可作為參考；正式設定改變時依影響範圍補驗，不能直接沿用通過結論。

最後填新表第 6 節，核對兩家 ZIP 雜湊、實際公司設定、文件版本、證據及簽名／日期。
每輪依 SOP 保存停止、資料保留及資源收尾結果。所有必要項目完成才簽收；
人員未執行、文件未審閱或仍有失敗時，清單第 7～9 項繼續保持待完成。
