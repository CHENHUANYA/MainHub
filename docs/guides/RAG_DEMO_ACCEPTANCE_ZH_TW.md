# 查詢品質與展示操作

這份流程用來留下「問了什麼、文件寫了什麼、實際答了什麼」的可核對證據。
服務正常啟動、找到文件或自動檢查通過，都不能單獨代表答案正確。

## 示範資料準備

共用基礎包內有 CNC 與空壓機兩份題庫，包含正常查詢、未知代碼、缺少參數及另一公司設備問題。
文件全部是 **MOCK 訓練資料**，使用虛構的顏色與表單 ID，沒有真實設備設定值。
展示時請使用獨立示範部署，不匯入正式公司的知識庫。

發行方或展示準備人員在基礎目錄執行以下固定指令；不修改 Python 或題庫程式：

```powershell
.\.venv\Scripts\python.exe scripts/verify_company_rag_quality.py prepare --scenario cnc --output demo-cnc
.\.venv\Scripts\python.exe scripts/verify_company_rag_quality.py prepare --scenario compressor --output demo-air
```

輸出目錄須尚不存在。每包包含文字型 PDF、`questions.md` 問題卡與 `suite.json` 頁碼／檔案雜湊。
兩位展示人員可直接取得已產生的示範包；不必自行產生 PDF。

## 畫面展示順序

1. 依 [公司導入 SOP](COMPANY_DEPLOYMENT_SOP_ZH_TW.md) 建立 CNC 或空壓機示範部署，套用相應公司設定。
2. 登入管理後台，在正確知識庫匯入該領域的 MOCK PDF。記錄檔名與匯入結果。
3. 以有權限的操作員選擇對應設備，將問題卡的問題原樣輸入，保留完整回答、引用及回答 ID。
4. 打開原 PDF 的預期頁碼，逐句比對回答。正向題須核對動作、對象、識別碼與來源類型。
5. 繼續詢問未知代碼、缺少參數及另一領域設備。應直接說明資料缺口，不猜數值，不拿別的警報當答案。
6. 把通過與失敗都填入 [導入驗收紀錄表](../../templates/COMPANY_ACCEPTANCE_RECORD_ZH_TW.md)。失敗答案與來源截圖一起保留。

| 領域 | 有答案的問題 | 正確來源 | 缺資料情境 |
| --- | --- | --- | --- |
| CNC | 3101 記錄 BLUE 與觀察時間；3102 把訓練表及工作表 ID 交給維修團隊 | `MOCK-cnc-manual.pdf` 第 1／2 頁 | 3999、主軸扭矩、AIR-01／E-42 |
| 空壓機 | E-42 記錄 VIOLET 與觀察時間；E-43 將 Q-17 交給維修團隊 | `MOCK-compressor-SOP.pdf` 第 1／2 頁 | E-99、安全壓力上限、CNC-01／3101 |

## 判定方式

每題分別記錄下列結果，任何必要項目未通過都保留為失敗，不能挑選另一個回答取代原始失敗紀錄：

- **檢索**：預期文件與頁碼是否出現在結果中。
- **引用**：畫面來源是否能對回原 PDF；回答文字有沒有引用錯頁、不存在的檔案，或把模擬文件稱為官方手冊。
- **內容**：每個事實與動作是否有原文支持；不能只看關鍵字出現。
- **表達**：一般維護回答先列「原文摘錄」，再列「繁中說明」與來源；英文問題也須有繁中說明。
  CNC 明確警報查詢保留完整原文，不把沒有翻譯當成錯誤。MOCK 須在正文說明是訓練資料、非操作指引，
  不能只靠來源檔名含 `MOCK` 算通過。
- **資料不足**：是否明確說明缺少哪份證據，且未猜測參數或輸出不相關的處置。
  限定為「本次檢索內容」的缺口，並索取對應文件，例如設備壓力規格或型號對應扭矩規格。
- **可重做**：記錄版本、模型、公司設定、問題、完整回答及時間；修正共用版本後用原題重跑，保留前後結果。

正式公司驗收要換成自己的核准文件與題目，至少涵蓋兩題有答案、兩題資料不足與一題設備不符。
MOCK 題通過只證明這組示範資料的行為，不代表正式設備文件或任意問題的品質已驗收。
正式文件版本、設備適用證據、五題覆蓋及逐句審閱欄位見
[正式公司驗收準備](FORMAL_ACCEPTANCE_PREPARATION_ZH_TW.md)，每家公司各留一份紀錄。

## 工程自動檢查

工程人員可對初始化工具產生且明確標記 `demo-` 的部署使用：

```powershell
.\.venv\Scripts\python.exe scripts/verify_company_rag_quality.py run --deployment "示範部署目錄" --suite demo-cnc/suite.json --output "新的證據目錄"
```

工具會建立示範管理員的測試密碼、套用同領域設定並匯入 PDF；既有不相干文件會使驗收停止，不自動清除。
只有隔離工程部署使用這條指令；不同人獨立依 SOP 操作的驗收仍須走畫面流程。
自動檢查涵蓋回答來源、快照、檔案雜湊、頁碼、必要詞語及缺資料訊號，結果仍要求逐句審閱。
正向題要求真實 Ollama 回答；缺資料題可由 Ollama 說明缺口，或由 `evidence_guard` 在生成前拒絕不符的識別碼。
後者的回答紀錄會明列 `provider=evidence_guard`、空白模型欄位，不算模型成功回答。
此檢查針對英數字與連字號組成的識別碼（例如 AIR-01／E-99）及明確數字警報碼，
逐一確認它們是否出現在本次檢索原文或警報 metadata；檔名本身不算內容證據。
缺少任一識別碼時說明本次檢索不足，不宣稱整個知識庫沒有該資料。一般數值問題與未明示的設備仍須靠來源審閱。
正向題另要求回答正文包含預期檔名與頁碼；只有檢索 metadata 含正確來源不能算引用通過。
文字檢查支援 `檔名，第 1 頁`、`檔名, Page 1`、`檔名, P.1` 及 `[Page 1 | Source: 檔名]` 等格式，
仍不能代替每項事實的人工比對。

題庫的 `answer_contract` 分別為 `excerpt_zh`、`verbatim`、`insufficient_zh`。
一般維護正向題檢查指定原句是否在摘錄區、繁中動作與對象是否在說明區、MOCK 非操作聲明是否存在；
CNC 正向題核對完整原文章節（僅忽略排版空白）；不足題檢查檢索範圍與索取文件。
這些是格式及詞語檢查，不能證明翻譯正確、語意相關或未夾帶其他錯誤事實。
先前已產生的 `suite.json` 不會自動更新，補驗須重新 `prepare` 到新目錄，保留舊問題卡與結果。
執行工具會拒絕沒有明列表達要求的舊題庫，並在報告記錄檢查版本及題庫 SHA256。
補件檢查只核對「請提供」之後實際索取的文件，不把前面提過壓力或扭矩當成已索取其規格。

檢索原文出現 `MOCK` 或「模擬資料」時，程式會在回答前加上
「本次檢索包含 MOCK 訓練資料，非實際設備操作指引。」串流與非串流使用相同標示並保存至回答紀錄。
此聲明只指出檢索集合含有模擬內容；混合正式與模擬文件時，仍須逐項核對引用的來源性質。

一般維護回答送出前會核對摘錄、繁中說明及檔名／頁碼；摘錄文字須能在本次原文找到。
格式缺漏時最多重新生成一次；仍未通過就回覆「本次未提供完整回答」，
保存為 `provider=answer_guard`、`answer_state=fallback`、空白模型欄位，不得計為驗收成功。
資料不足回答若補件過於空泛，程式會依問題補上壓力規格、扭矩規格、警報手冊或設備適用文件。
這不會提供任何設備設定值，也不代表已證明文件間的適用關係。

一般維護的串流會在核對完成後才送出回答，第一段文字可能較晚出現；SSE 的回答 ID、引用、結束事件與快照規則不變。
CNC 明確警報逐字查詢仍保留原生逐段串流。格式核對不等於翻譯、設備關係或全部事實都經過語意驗收。

## 設備對照與拒答邊界

公司設定的設備對照選擇知識庫，**不替文件提供設備適用性證據**。
目前識別碼防護只做必要字面核對，通過防護代表可進入生成，不等於內容已通過語意驗收。

| 查詢及本次取得的原文 | 應有行為與判定依據 |
| --- | --- |
| 問 AIR-01／E-42；同段原文明列 AIR-01／E-42 與記錄動作 | 可依該句回答並引用來源；仍逐句核對動作及對象 |
| AIR-01 已對照空壓機知識庫，但通用手冊未提 AIR-01 | 明問 AIR-01 時保守拒答，索取適用性或對應設備文件；對照設定不能覆蓋缺口 |
| 不指定設備，只問「這份訓練手冊要求記錄什麼」 | 可摘錄該手冊明列內容；不能自行套用到 AIR-01 |
| 只有檔名 AIR-01.pdf 含識別碼，內文未提 AIR-01 | 檔名不是適用性證據，仍拒答 |
| 問 AIR-01／E-42；片段一是 AIR-01 出席紀錄，片段二是 AIR-02／E-42 步驟 | 字面防護可能通過，但沒有 AIR-01／E-42 關係證據；應說明缺口，不借用 AIR-02 步驟；人工審閱不可判為可處置 |
| 問 `3101, 3999`，本次只取得警報 3101 | 每個數字警報都核對，說明缺少 3999，不用 3101 代答 |
| 問壓力上限，原文只寫記錄讀值 | 沒有設定值證據，索取壓力規格；不得猜數值 |

支援的 `text_v1` 以文字型 PDF 的段落及頁碼作來源，`sinumerik_alarm_v1` 另使用解析到的警報碼。
掃描 PDF 沒有可擷取文字時須先處理 OCR；單純改設備對照不能補出原文。
以上缺口均只表示本次檢索不足，不表示整個知識庫沒有資料。

另有 `grounding` 回歸包，保留曾把「儀表讀值／通報維修」答成第 3 頁「訓練出席」的原題：

```powershell
.\.venv\Scripts\python.exe scripts/verify_company_rag_quality.py prepare --scenario grounding --output demo-grounding
```

此包使用空壓機公司設定與三頁 `MOCK-compressor.pdf`，含原英文題、中文題與三題資料不足／設備不符情境。
工程驗收使用全新的空壓機示範部署，避免與另一套示範 PDF 混合；不清除既有公司的文件。

中文查詢目前依既有規則使用 BM25／向量／RRF 排序，跳過英文 reranker；
工具另外以英文檢索確認 reranker 可執行，將兩者分開記錄。不能將英文探測結果當成中文回答用了 reranker。
