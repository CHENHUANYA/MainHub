## 已完成的實作

### 1. 公司設定與動態選單

主要程式：`services/company_config.py`、`services/system_settings.py`、`routes/settings_routes.py`，
以及 `static/js/` 的角色頁面。

設定包使用 JSON，並驗證版本、重複 ID、預設知識庫、設備／產線參照及受控模組名稱。
執行時設定保存在 JSON 或 PostgreSQL；再次套用需通過版本檢查。

新增紀錄優先依設備對照選擇知識庫。明確指定的設備、產線或知識庫互相衝突時拒絕寫入。
修改設備與產線也會驗證；不涉及設備對照的修改仍可處理歷史紀錄，不改寫舊知識庫 ID。

### 2. 文件解析與回答領域

主要程式：`ingest.py`、`services/prompt_profiles.py`、`app_context.py` 與相關查詢／匯入路由。

| 名稱 | 用途 |
| --- | --- |
| `sinumerik_alarm_v1` | 沿用 SINUMERIK 警報手冊切分 |
| `text_v1` | 文字型 PDF／SOP，不要求警報碼，保留短行、字母設備代碼與頁碼 |
| `cnc_maintenance_v1` | CNC 手冊與診斷提示詞 |
| `maintenance_v1` | 一般設備提示詞，不預設 CNC 警報分類 |

畫面上傳與 CLI 使用相同設定。段落保留文件 ID、檔名、頁碼、段落 ID、解析器與知識庫。
無文字可擷取時回報 OCR 限制。提示詞要求引用來源、區分模擬與正式內容，並說明資料不足；
這些程式規則不等於模型生成品質已經合格。

### 3. 地端模型與部署檢查

主要程式：`services/llm_clients.py`、`scripts/preflight_check.py` 與 Compose 設定。

- 預設模型改為 [Ollama `gemma4:e2b`](https://ollama.com/library/gemma4:e2b)。
- 程式、環境範例、目前 `.env` 與操作文件的預設值同步。
- 本機推論失敗不呼叫學校 API 或其他外部 LLM。
- 啟動檢查可要求 Ollama 服務、指定模型與 RAG 快取均已備妥。
- n8n 為選用服務，只在啟用 `automation` 時納入必要檢查。
- 新部署缺少尚未建立的資料目錄時列為提醒，不要求保留前公司的資料。

模型首次下載與套件／映像準備仍需網路；離線執行需先準備完整依賴。

### 4. 模擬後端流程驗證

指令：

```powershell
python scripts/verify_company_workflows.py --output outputs/company-demo-new-run
```

另外驗證權限、錯誤對照、重複派工、版本衝突、重新開案政策、索引重載，以及 B 執行後 A 資料不變。
